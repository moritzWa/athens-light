How to read and edit CLAUDE.md, AGENTS.md and plan files on Mac

Moritz Wallawitsch · November 19, 2026

AI coding agents write their instructions, plans and notes as markdown files. You can read them in a terminal or a code editor, but you see raw symbols. This page shows where each tool keeps its files and how to open them as formatted text on a Mac.

The short answer

  • Where: CLAUDE.md in the project root or ~/.claude/ for Claude Code, AGENTS.md for Codex and OpenCode, .cursor/rules/*.mdc or AGENTS.md for Cursor. Claude Code plans are in ~/.claude/plans/.
  • How to open one as formatted text: install Athens Light (free, open source, Apple silicon) and run open -a "Athens Light" CLAUDE.md.
  • How to keep it open while the agent works: the window reloads within about a second when the agent rewrites the file, and your caret stays put. If you have unsaved edits, it asks before it replaces anything.

I checked every file location below against each tool's own documentation on November 19, 2026. I tested the reload and the conflict bar in a macOS 26 virtual machine, and the screenshots are from it.

A few details from those docs:

  • Claude Code also reads AGENTS.md from version 2.1.277. By default it does so only when there is no CLAUDE.md in the working folder or above it. A CLAUDE.md that contains @AGENTS.md loads both.
  • Claude Code reads a plan back from disk after it compacts a long conversation, so the plan file is the real plan, not only the chat message.
  • Claude Code deletes old plans in ~/.claude/plans/ after 30 days by default. Set plansDirectory to ./plans in .claude/settings.json to keep them in the project.
  • Claude Code strips block-level HTML comments from CLAUDE.md before it sends the file to the model.

Why these files are hard to read raw

They are written for the agent first. A tool table is rows of pipes and dashes. Nested lists are indented dashes. Plan files have headings, checklists and code fences. Claude Code's own docs suggest keeping a CLAUDE.md under 200 lines, which is already a long scroll of symbols.

cat and less in Terminal print the raw text. Quick Look in Finder shows it too. Visual Studio Code opens a .md file as source, and its Markdown preview is a second pane you open with Cmd+K then V. Its docs also describe an experimental Markdown Editor that edits rendered text. A code editor works, but it is a large app for reading one file.

The second problem is that these files are not yours alone. The agent edits them while you read. A normal editor makes you notice that and reload.

How to open one as formatted text

  1. Install Athens Light. It runs on Apple silicon Macs. In Terminal: 
    curl -fsSL https://athens-light.app/install.sh | sh
    Or download the disk image from GitHub.
  2. Open the file. From your project folder: 
    open -a "Athens Light" CLAUDE.md
    For your personal file, use open -a "Athens Light" ~/.claude/CLAUDE.md. Finder hides ~/.claude, so in Finder press Cmd+Shift+G and type the path, or press Cmd+Shift+. to show hidden folders.
  3. Make it the default for .md files if you want a double-click to work. Select a .md file, press Cmd+I, pick Athens Light under Open with and click Change All. More on opening .md files.

The file opens as a title, headings, lists, a table and links. Click and type to edit. Changes save to the same file about 0.4 seconds after you stop typing.

Keep the file open while the agent rewrites it

This is the reason I use it for agent files. Athens Light checks the open file once a second. When something else changes it, the window updates by itself. That covers an agent that overwrites the file, a git checkout, and a tool that replaces the file with a new one.

Here is a CLAUDE.md open in the app. The caret is at the end of "Named exports only."

Then something outside the app rewrites the file. In this test it was a short script that adds a bullet under Code style and a Notes section at the end. It overwrites the file in place, which is what an agent's edit tool does. I did not run a live Claude Code session for this.

The new bullet was on screen when I took the screenshot 2.5 seconds after the write. I did not click or press anything. I also ran git checkout CLAUDE.md to put the old version back, and the window followed that too.

What happens when you and the agent both edit

If you have unsaved edits at the moment the file changes, Athens Light does not replace your text and does not write over the agent's. It pauses autosave and shows a bar with three choices:

  • Keep mine. Your version is written to the file.
  • Take theirs. Your unsaved edits are dropped and the window shows the file as it is on disk.
  • Keep both. The window shows the file on disk. Your version is saved next to it as CLAUDE (my edits 2026-11-19 14.44.07).md.

I tried Take theirs and Keep both. Take theirs left the file as the agent wrote it. Keep both created the extra file in the same folder, and git status listed it as untracked. Delete it when you are done. This matters most in .claude/rules/, because Claude Code loads every .md file in that folder as a rule.

You only see the bar when your edits are not yet saved. Autosave runs 0.4 seconds after you stop typing, so in practice it shows up when you are typing as the agent writes.

Limits you should know

  • The first edit rewrites the file in the editor's style. Opening a file never changes it. After my first keystroke, the tool table in the test file changed like this: 
    -| Name | URL | Deploy |
-| --- | --- | --- |
-| staging | https://staging.acme.test | on merge to `main` |
+| Name       | URL                                                    | Deploy             |
+| ---------- | ------------------------------------------------------ | ------------------ |
+| staging    | [https://staging.acme.test](https://staging.acme.test) | on merge to `main` |
    The columns were padded and the bare URL became a link. The meaning is the same, but the diff is bigger than your edit. Bullet characters and spacing can change too. If a file must stay byte for byte the same, use a plain text editor.
  • Files with raw HTML open read-only. A <details> block was enough to trigger it. The window shows "Read-only: this file has HTML, which Athens Light can't save". HTML comments are fine.
  • Apple silicon only. There is no Intel, Windows or Linux build.
  • It is an editor, not a viewer for a whole project. There is no file tree and no outline, and it does not export. You open one file at a time, as tabs.
  • Editing a file does not change a running agent. Claude Code's docs say it loads CLAUDE.md files at the start of a session. OpenCode's docs say it notices edits to AGENTS.md before its next request. I tested the editor side only, not how each agent reacts.
  • Cursor .mdc files need Terminal. open -a "Athens Light" rule.mdc opens the file as formatted text and hides the front matter. Finder double-click and the Open File dialog only list .md and .markdown. I opened an .mdc file but did not edit one.

Questions

Where is the CLAUDE.md file?

In your project it is ./CLAUDE.md or ./.claude/CLAUDE.md. Your personal one is ~/.claude/CLAUDE.md, and a private one for one project is ./CLAUDE.local.md. On macOS an organization can also set one at /Library/Application Support/ClaudeCode/CLAUDE.md. Run /memory inside Claude Code to list the ones it found.

How do I open CLAUDE.md on a Mac as formatted text?

Install a markdown editor that shows formatted text, then run open -a "Athens Light" CLAUDE.md, or set it as the default app for .md files. The steps are above. I compared six such editors if you want another one.

Can I edit a markdown file while the agent is writing to it?

In Athens Light, yes. The window reloads within about a second and keeps your caret. If you have unsaved edits, the bar asks which version to keep.

Where does Claude Code save its plans?

In ~/.claude/plans/ by default. Each plan is its own markdown file. The plansDirectory setting moves them into your project. Press Ctrl+G in Claude Code to open the plan in your default text editor before you approve it.

Does Claude Code read AGENTS.md?

Yes, from version 2.1.277. By default it reads AGENTS.md only when you have no CLAUDE.md in the working folder or above it. To use both, add @AGENTS.md to your CLAUDE.md.

What if CLAUDE.md is a symlink to AGENTS.md?

I tested this. Athens Light writes through the link. The symlink stays and AGENTS.md gets the change. The window title shows the target's name, AGENTS.md.

Is it safe to let an editor and an agent share a file?

The editor never writes over a change it has not looked at. It checks the file before each save. If the file changed and you have unsaved edits, it stops and asks. The one cost is the style rewrite on your first edit.
